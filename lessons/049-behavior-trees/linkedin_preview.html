Behavior trees become useful when a robot must choose what matters most right now—and keep making that decision as the world changes.

In this Professor OS lesson, students:

• Compare behavior trees with state machines
• Trace reactive selectors and memory sequences one tick at a time
• Distinguish branch status from complete mission status
• Implement SUCCESS, FAILURE, RUNNING, preemption, halting, and timeouts in Python
• Extend the simulation with a persistent safety guard

The lesson also makes an important engineering distinction: clearing a simulated drive flag is not proof that a physical robot has stopped. Real action interfaces must define cancellation, resource ownership, and verified safe-stop behavior.

Try the lab, change the priority structure, and observe how one node’s status changes the entire mission. What safety behavior would you place above delivery in your own robot?
