Welcome to Professor OS. This is Class 55, Q-Learning with a Grid Robot. In the previous class, we introduced reinforcement learning. A robot tries actions, receives rewards or penalties, and gradually improves its behavior. Today, we make that idea concrete with RoboRover, a small robot moving through a grid. The central sequence is simple: state, action, reward, updated knowledge. RoboRover’s software is the agent. The grid, including its obstacles and goal, is the environment. At each step, the robot observes a state, chooses an action, receives a reward, and moves to a new state. In this lesson, a state is just the robot’s grid coordinate: its row and column. An action can be Up, Right, Down, or Left. The reward tells the robot whether the result was useful. Ordinary movement might receive a penalty of minus one point, reaching the goal might receive plus ten, and trying to enter an obstacle or leave the grid might receive minus three. These rewards are not physical forces. They are numerical teaching signals. RoboRover stores its learned knowledge in a Q table. Imagine a notebook with one row for every possible state and one column for every action. Each entry answers this question: if I am in this state and choose this action, how promising is that choice? That entry is called a Q value. A high Q value estimates a larger expected discounted cumulative reward. It is not a probability, a percentage, or a guarantee. It is a prediction based on what the robot has learned so far. For example, suppose the Q values at one square are as follows: Up is 2.1, Right is 5.7, Down is minus 1.0, and Left is 0.4. The current best choice is Right, because it has the largest estimated value. Q-learning balances exploration and exploitation. Exploration means trying actions to discover what happens. Exploitation means choosing the action currently believed to be best. If RoboRover only exploits too early, it may commit to a poor choice and never discover a better route. Let’s work through one update. Suppose RoboRover is one square to the left of its goal. It chooses Right and reaches the goal. Its old Q value for choosing Right was zero reward points. Reaching the goal produces a reward of ten points. The learning rate is one-half, and the future value after reaching the goal is zero because the episode ends there. The target is ten plus zero, which is ten points. The update moves the old value halfway toward that target. So the new Q value is zero plus one-half times ten minus zero, giving five reward points. After just one successful experience, moving Right from that state has become valuable. Later, useful information can spread backward. A square two moves from the goal can learn that an action from there eventually leads to this valuable goal transition. That propagation of future value is one of the most important features of Q-learning. The general update follows the same logic. Start with the old Q value. Build a target from the immediate reward plus the discounted best estimated value in the new state. Then move the old estimate toward that target by an amount controlled by the learning rate. The discount factor controls how strongly future rewards matter. The learning rate controls how strongly each new experience changes previous knowledge. Both are dimensionless parameters, usually between zero and one. Pause and predict: if the old Q value is 2.0 points, the target is 6.0 points, and the learning rate is one-quarter, what is the new value? Brief pause. The prediction error is 6.0 minus 2.0, or 4.0 points. One-quarter of that is 1.0, so the updated Q value is 3.0 points. The Python lab builds this idea in a deterministic four-by-four grid. The program initializes Q values, defines what happens after each action, and trains over many episodes. During training, an epsilon-greedy policy sometimes chooses a random action for exploration and otherwise chooses an action with the largest current Q value. Epsilon gradually decreases, but it does not reach zero. The Q-learning update uses the reward and the best future Q value from the next state. After training, a greedy path follows the highest-valued action without random exploration. Assertions check that this particular run reaches the goal in no more than eight moves. Those checks verify this fixed experiment; they do not guarantee that every Q-learning system will always succeed. The most important engineering caveat is that a learned table is useful, but it is not automatically reliable on real hardware. In a clean grid, moving Right can mean moving exactly one square. On a physical rover, wheels can slip, sensors can be noisy, actions can be delayed, and battery or floor conditions can change. A state that contains only a grid coordinate may also be missing important information. For example, it may not tell the robot that another moving object is approaching. State design is therefore an engineering decision. If states are too coarse, situations requiring different actions may be treated as identical. If states are too detailed, the table can become enormous and difficult to train. Unsafe exploration is another concern. Trying a bad action in simulation may cost a few reward points. Trying it on a real machine could damage equipment. For that reason, learning is often done in simulation first, followed by carefully limited real-world testing. A safety controller may override dangerous actions. That safety layer surrounds the learning system; it is not itself part of the Q table. The practical takeaway is this: Q-learning is a way to connect experience with action preferences. Define a useful state, define the available actions, choose rewards that encourage the behavior you want, and update the Q value after every transition. Then inspect the learned policy rather than assuming the table is correct. To recap, RoboRover observes a state, chooses an action, receives a reward, and updates its estimate. The Q table stores estimated discounted future reward for each state-action pair.
